# AI Testing in Flag Manifolds

Final project for the MM845 course at the University of Campinas (UNICAMP), exploring computational and AI methods for Coxeter diagrams and flag geometry.

This repository studies when a labelled Coxeter diagram is **spherical**—equivalently, when its Cartan/Gram matrix is positive definite—and whether a learned policy can turn a randomly generated diagram into a spherical one through local edge edits. The project combines an exhaustive check for small diagrams with a Proximal Policy Optimization (PPO) agent and experiment notebooks.

## Project overview

Each diagram is represented by a symmetric matrix. Off-diagonal labels are drawn from `(2, 3, 4, 6)`, where `2` means no edge. The environment's action chooses an unordered vertex pair and one of those four labels to write on that pair. Dataset A samples dense, uniform initial diagrams; Dataset B samples sparser diagrams. The PPO policy is a small graph neural network implemented directly in PyTorch.

The main components are:

- `src/coxeter.py`: diagram representation, Cartan matrix, spherical test, and margin.
- `src/exhaustive.py`: permutation-symmetry-aware exhaustive search for small diagram sizes.
- `src/datagen.py` and `src/env.py`: initial-diagram distributions and the editing environment.
- `src/policy.py` and `src/train_ppo.py`: graph policy and terminal-based PPO training.
- `src/analyze.py`: checkpoint evaluation, type summaries, and training curves.
- `notebooks/`: benchmarks, structural analysis, training-history comparison, and inference.
- `results/`: generated checkpoints, training logs, baselines, and analysis outputs. Not every file in this directory is generated by the same branch or experiment; see [Branches and experiment provenance](#branches-and-experiment-provenance).

## Branches and experiment provenance

## Environment setup

The repository does not currently include a dependency lockfile or environment manifest. The project was exercised with Python 3.12 and uses NumPy and PyTorch for the core code. The notebooks additionally use pandas, Matplotlib, and Jupyter/IPython. PyTorch's recommended install command depends on your operating system and whether you need CUDA; use the official [PyTorch installation selector](https://pytorch.org/get-started/locally/) for that package if the generic pip installation does not match your system.

From the repository root, create and activate a virtual environment, then install the notebook dependencies and PyTorch:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy pandas matplotlib jupyter ipykernel torch
```

On macOS or Linux, the corresponding environment activation is:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy pandas matplotlib jupyter ipykernel torch
```

The PPO training and command-line analysis scripts need only NumPy and PyTorch. Notebooks 03 and 04 also need pandas, Matplotlib, and a Jupyter kernel. Select the environment created above as the notebook kernel. On Windows, the training script sets `KMP_DUPLICATE_LIB_OK=TRUE` to work around a common OpenMP library conflict.

## Train PPO from the terminal

Run commands from the repository root. Training is a terminal script, not a notebook operation. On `main`, the script accepts datasets A/B, vertex count, episode horizon, seed, total timesteps, and a checkpoint directory. Each command below writes to a separate directory, so the six comparison runs do not overwrite one another:

```powershell
python -m src.train_ppo --dataset A --n 8 --max-episode-steps 30 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/A_seed0_Nfixed8
python -m src.train_ppo --dataset A --n 8 --max-episode-steps 45 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/A_seed0_steps45_Nfixed8
python -m src.train_ppo --dataset A --n 8 --max-episode-steps 60 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/A_seed0_steps60_Nfixed8
python -m src.train_ppo --dataset B --n 8 --max-episode-steps 30 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/B_seed0_Nfixed8
python -m src.train_ppo --dataset B --n 8 --max-episode-steps 45 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/B_seed0_steps45_Nfixed8
python -m src.train_ppo --dataset B --n 8 --max-episode-steps 60 --seed 0 --total-timesteps 2000000 --checkpoint-dir results/B_seed0_steps60_Nfixed8
```

Run one command at a time. For a shorter smoke test, reduce `--total-timesteps` (for example, to `100000`); a short run verifies the environment and output generation but does **not** reproduce the reported training horizon. The current defaults use 16 environments and 64 rollout steps per update. Since updates advance by 1,024 environment steps, a request for 2,000,000 timesteps completes at 1,999,872 steps.

Each run directory receives `checkpoint_latest.pt`, periodic `checkpoint_step_<steps>.pt` checkpoints, and `train_log.npz`. The NPZ contains the arrays `timesteps`, `reward`, `margin`, and `success_rate`. The 30-step A and B runs above produce the two final checkpoint paths consumed by notebook 04. The six run logs are the inputs to notebook 03. Checkpoint and log paths can be changed with `--checkpoint-dir`.

For other N values on `main`, change `--n` (minimum 2). For another seed, change `--seed`. The A/B distributions are defined in [src/datagen.py](src/datagen.py): A uses probability 0.25 for no edge; B uses probability 0.75. Both use labels 3, 4, and 6 for present edges.

### Evaluate a checkpoint from the terminal

After training the 30-step A and B runs, evaluate a checkpoint with:

```powershell
python -m src.analyze --checkpoint results/A_seed0_Nfixed8/checkpoint_latest.pt --n-episodes 500 --dataset A
python -m src.analyze --checkpoint results/B_seed0_Nfixed8/checkpoint_latest.pt --n-episodes 500 --dataset B
```

Add `--deterministic` to use argmax actions. The analysis command looks for `train_log.npz` beside the checkpoint and, when found, writes a training-curve figure there. For the matched stochastic-policy and baseline comparison, use notebook 04; it evaluates frozen checkpoints and does not train or tune them.

## Reproducibility notes

- PPO and environment randomness are seeded; GPU and library versions can still affect bit-for-bit reproducibility.
- Results are stochastic estimates. Compare the logged curves and evaluation intervals rather than expecting identical outputs on every machine.
- `checkpoint_latest.pt` and `checkpoint_step_<steps>.pt` are binary training state files; the latter are periodic recovery checkpoints, not extra notebook inputs.
- To reproduce the curriculum experiments, switch to `variable-N` and follow that branch's own code and notebook version. Do not substitute the fixed-N `main` commands without checking that branch's training interface and intended configuration.
